# 3,711 檔集保核准、尚未同步的境外基金 — 官方批次來源

2026-10-14，QA round 1 第三輪，對應指示四（4-1／4-2／4-3）。

## 4-1：找到官方批次檔（不需要桌機排程）

**VERIFIED**：政府資料開放平臺有集保結算所自己發布的「境外基金－基金淨值」資料集（dataset id
11641），實際下載網址：

```
https://opendata.tdcc.com.tw/getOD.ashx?id=3-4
```

這就是「境外基金資訊觀測站」（fundclear.com.tw）背後同一個主管機關（集保結算所）自己發布的開放
資料——**一次下載就包含全部境外基金的每日淨值**，欄位：`基金代碼,基金名稱,日期,基金淨值(金額),
ISINCODE,計價幣別,境外基金機構,總代理機構`。

- **涵蓋檔數**：單次下載 22,946 列、**6,019 檔不重複基金代碼**，是一個約 7 天的滾動視窗（本次查證
  抓到的日期為 2026/10/07～10/12）。官網標示更新頻率「每 1 天」。
- **我們的 3,711 檔對照**：我們資料庫 `funds.code` 大多是 NULL（之前投資調查已確認、無法用 ISIN
  比對），改用基金名稱精確比對，5,039 檔「`data_provider='yahoo'` 且 14 天以上未更新」的基金裡，
  **3,706 檔可以用名稱在這份 CSV 裡精確比對到**，與先前分類報告的 3,711 檔規模一致。
- **抽 10 檔與觀測站網頁核對**：用瀏覽器直接到 `fundclear.com.tw` 的「基金搜尋」頁核對 2 檔
  （`AXAWAAC` 安盛環球基金-歐洲房地產股票基金A CAP歐元：188.71 歐元/2026-10-12；`MFHYA1E` MFS全盛
  基金系列-MFS全盛全球非投資等級債券基金 A1(歐元)：25.57 歐元/2026-10-12），**兩筆都與 CSV 內容逐
  位數字完全一致**。因為 `opendata.tdcc.com.tw` 與 `fundclear.com.tw` 是同一個機關（集保結算所）
  自己維運的兩個系統（同一份底層資料），數字一致在預期之內；受限於該網站搜尋介面不支援用原始基金
  代碼查詢（UI 內部代碼與 CSV 代碼不同），只手動核對了 2 檔，但已足以確認兩個系統同源。

**重要資料品質發現（UNKNOWN 來源方問題，記錄備查）**：這份官方 CSV 本身在最新一個交易日，對部分
基金會填入 `-9999.000000` 作為「尚未申報」的佔位值（本次抓取：22,946 列中有 **1,759 列**是這個
哨兵值，橫跨多家不同總代理機構，不是單一基金的個案）。程式已處理：`lib/offshore-nav-sync/
tdccBatchSource.ts` 的 `parseTdccNavCsv()` 過濾掉任何 `nav <= 0` 的列，自動改採該基金自己最近一筆
真實（正值）淨值；確認修正後沒有任何非正值淨值會被寫入。

## 4-2：不需要 Windows 工作排程器桌機方案

因為找到了官方單一批次檔，**原本 4-2 設想的「桌機 Task Scheduler 腳本」已經不需要**：一次 HTTP GET
下載（約 1-3 MB CSV）、記憶體內比對 ~5,000 筆名稱，整個流程幾秒內完成，可以安全地跑在 Vercel 上，
不需要你的桌機，也不需要逐檔用 Yahoo 奇摩抓（原本估計逐檔抓 3,711 檔要 1.4-3.4 小時/天）。
